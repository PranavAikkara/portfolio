01

Vectorless retrieval

2025

Retrieval over large enterprise document sets with no vector store and no embedding index to maintain. The model navigates a structured outline and opens only the passages it needs, so every answer cites a real page instead of a fuzzy similarity score. The unexpected win was honesty: it says "not in these documents" rather than inventing a confident, wrong passage.

02

Conversational voice agents

2025

Telephony-grade agents that take a call, understand intent over a noisy line, and complete a task end to end. The speech models were the easy part. The real engineering was the dialogue manager, barge-in handling, and shaving milliseconds off a latency budget that the caller measures in awkward silence.

03

Resilient document ingestion

2024

A pipeline for the documents nobody wants to parse: skewed scans, merged cells, two languages on one page. It normalises layout before content, so everything downstream receives clean, ordered text. The principle that carried it: fix structure first, meaning second. Half of what looked like model problems were data problems in disguise.

OCRLayout parsingMultilingualPipelines
04

Fine-tuned small models

2024

For a tightly-scoped task, I fine-tuned a small open model that was faster, cheaper, and fully under our control. The interesting part was the data: synthetic examples added breadth but quietly skewed the distribution until the eval caught it. Knowing when to stop mattered more than any hyperparameter.

05

How I work

A

Start with the eval

I build the ruler before I trust any result. If I can't measure good, I can't ship it.

B

Make it traceable

Every output should point back to a source. No black boxes shipped to people who'll be held accountable for them.

C

Respect the latency budget

Speed isn't polish. In voice and search it's the difference between usable and abandoned.

D

Plan for 3am

Fallbacks, logging, and a clear failure mode. The system has to behave when I'm asleep.
