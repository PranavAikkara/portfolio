The case files.

Four systems that ran in production. For each: what it does, the hard part, and the thing I'd warn the next engineer about.

[001]

Vectorless retrieval

case_001 — retrieval
describe --what
retrieval over large document sets with no vector store. the model reads a
structured outline, opens only the sections it needs, and cites the page.
 
describe --hard-part
getting the model to say "not in these documents" instead of inventing
a confident, wrong passage. honesty was the feature, not accuracy.
 
describe --warning
documents with zero structure. no outline to navigate means you build one
first, which is its own project. budget for it.
[002]

Conversational voice agents

case_002 — voice
describe --what
telephony-grade agents that take a call, understand intent on a noisy line,
and complete a task end to end. with barge-in and graceful recovery.
 
describe --hard-part
latency. recognition + reasoning + synthesis all share a budget the caller
measures in silence. most of the work was shaving milliseconds.
 
describe --warning
never optimise the speech model first. the dialogue manager and turn-taking
logic is where the project actually lives.
[003]

Resilient document ingestion

case_003 — ingestion
describe --what
a pipeline for the documents nobody wants: skewed scans, merged cells,
two languages in one paragraph. layout normalised before content.
 
describe --principle
fix structure first, meaning second. get reading order right and half the
"AI problems" downstream turn out to have been data problems.
 
describe --warning
if a human can't tell the reading order at a glance, the parser won't
either. that page needs a different strategy, not a better prompt.
[004]

Fine-tuned small models

case_004 — fine-tuning
describe --what
a small open model fine-tuned for one narrow task. faster, cheaper, fully
owned, and good enough to retire the frontier api call.
 
describe --hard-part
the data. synthetic examples added breadth but quietly skewed the
distribution until the eval caught it.
 
describe --warning
knowing when to stop > any hyperparameter. once it clears the bar a
human reviewer would, more training is polishing a corner nobody sees.
